## Why this skill exists

Most work fails not because the operator is unintelligent but because steps get
**skipped, reordered, or quietly guessed at** under pressure. This framework's
whole value is that it makes the sequence explicit and makes honesty about the
unknown structural rather than optional. Following it is how work gets built
*right the first time* instead of firefighting later.

## The one rule above all others — the Variable Principle

> *"Where measurement ends, create a variable. Hold it open. Map what IS
> measurable on either side. As the surrounding process is traced, the variable's
> range narrows. Sometimes it resolves by logical necessity. Sometimes it remains
> open. Never fill a variable with assumption."*

Apply this to **your own outputs**. For every claim, sort it into one of three
buckets and keep them distinct:

- **Measured** — you have the data / a source / a verifiable fact.
- **Derived** — it follows structurally from the framework or from measured facts.
- **Held-open** — not yet determined. Say so plainly. **Never fabricate a
  resolution to sound more confident.** This is the single most important rule;
  collapsing a held-open variable into a confident guess is the core failure mode
  the framework exists to prevent.

## How to run — the invariant form

Every piece of work runs the same shape:

1. **Route** the problem to a layer or algorithm — use the Router below (or
   `framework/algorithms.md`). If nothing named fits, run the **Master
   Meta-Algorithm** and *label the result a derivation*.
2. **Execute the numbered steps in order.** Do not skip, compress, or invert —
   the sequence is load-bearing.
3. **If a step cannot be completed, stop.** The blocker *is the location of the
   work* — name it, don't route around it silently.
4. **Document the run.** Per Layer VI Step 6: if it isn't written, it doesn't
   exist as a process. Record what algorithm ran, the steps, and the outcome.
5. **Integrate what deviated** (Layer I.G — the Capsule / Slime-Mold
   Integration). Every path explored becomes substrate for the next run; nothing
   is thrown away. This is why the framework iterates instead of restarting.

## When no algorithm fits — the Master Meta-Algorithm

The general engine. When the domain has no pre-specified algorithm, run the
12-step spine in `versions/v5.1/…#the-master-meta-algorithm` to **derive** one,
and label the result a *derivation*, not a primary algorithm. Do not improvise
silently and do not present a derivation as canon.

## Correspondence and derivations

- **State Correspondence explicitly** when the same algorithm applies at another
  scale ("as above, so below" — one scale up, one down). It's a feature, name it.
- **Label domain derivations** as derivations when you apply the framework to a
  domain it doesn't explicitly name.
- **Do not alter the base code.** Iterations operate *on* the base; they don't
  rewrite it. (Contributions follow the Iteration Protocol in `CONTRIBUTING.md`.)

## Faithfulness checklist (run before you finalize an output)

- [ ] Named the layer/algorithm used (or labeled the Master Meta-Algorithm derivation).
- [ ] Ran the steps in order — or explained exactly which step blocked and why.
- [ ] Marked every held-open variable as held-open; fabricated no resolutions.
- [ ] Kept measured / derived / held-open visibly distinct.
- [ ] Flagged empirical data the framework cannot supply (prices, real-time
      facts, specific measurements) and either retrieved it or named the gap.
- [ ] Attributed the framework: *GFunnel Methodology (Omni Process), Cameron Garlick.*

## What not to do

- Do not present a derived algorithm as a primary one.
- Do not resolve a variable the framework marks open.
- Do not claim the framework proves something it lists as a live hypothesis or
  proven-open (see v5.3 §6 and `registers.md`).
- Do not skip steps to reach a conclusion faster — the skip is the bug.
